The hospital will continue losing time and money due to unused appointment slots, manual work, and booking errors. Patient dissatisfaction may increase, affecting the hospital's reputation and revenue.

AI-Powered Business Analyst Tool
MVP Feature Requirements Document
1. Data Input & Project Configuration
The application must allow users to provide unstructured business information through multiple input methods.
1.1 Input Methods
* Text Box: Paste meeting notes, emails, WhatsApp conversations, call transcripts, and other unstructured text.
* File Upload: Support .txt, .pdf, and .docx formats. All four provided messy sample files must be supported.
* Sample Data: Provide a button named "Load Hospital Sample Data" that automatically loads the City Care Hospital sample data for demonstration purposes.
* Clear Input: Allow users to clear all uploaded files and pasted content.
1.2 Project Configuration
* Project Name: Default example: Hospital Appointment System.
* Industry Dropdown: Healthcare, Banking, E-commerce.
* Allow users to enter or select a project name.
2. Master Prompt Management
The application must provide visibility and control over the AI instructions used for business analysis.
2.1 Master Prompt Features
* Display the complete Master Prompt before analysis.
* Allow users to edit the prompt before submitting it to the AI.
* Provide three predefined prompt templates:
1. Strict BA Prompt: Generates a detailed and structured final BRD.
2. Quick Analysis Prompt: Generates a short summary and identifies key requirements.
3. Conflict Finder Prompt: Focuses exclusively on identifying conflicts, duplicate requirements, and missing information.
Users should be able to switch between templates and customize the selected prompt.
3. AI Analysis Engine
Integrate the Google Gemini API to process the uploaded business information.
3.1 API Integration
* Accept the Gemini API key through the application sidebar.
* Never hard-code the API key.
* Allow model selection between Gemini 1.5 Flash and Gemini 1.5 Pro, subject to API availability.
3.2 Analysis Workflow
When the user clicks "Analyze Requirements", the application must:
* Combine the input data with the selected Master Prompt.
* Send the request to the Gemini API.
* Process the response into structured BA deliverables.
* Display a loading indicator with messages such as "Analyzing requirements..." and "Finding conflicts..."
3.3 Error Handling
Display clear error messages for:
* Invalid API key.
* Internet connectivity issues.
* Empty input.
* Unsupported file formats.
* API failures or response errors.
The application must never crash because of an API or input error.
4. Structured AI Output
The analysis results must be divided into five separate tabs instead of displaying everything in one long paragraph.
Tab 1: Problem Statement & Summary
Display:
* Business Problem: A concise 4–5 line explanation of the business problem.
* Key Stakeholders: List of all identified stakeholders.
* Success Criteria: Measurable conditions that determine whether the project is successful.
Tab 2: Requirements Table
Display requirements in a structured table.
Columns:
* Requirement ID
* Requirement Description
* Requirement Type (FR / NFR)
* Priority (High / Medium / Low)
Example:
* FR-01 | Patient can book appointments using UPI | FR | High
Filters:
* All Requirements
* Functional Requirements (FR)
* Non-Functional Requirements (NFR)
* High Priority Requirements
Tab 3: User Stories & Acceptance Criteria
Generate user stories using the standard format:
As a [User], I want [Feature], so that [Business Benefit].
Example:
As a Patient, I want to receive an SMS appointment reminder so that I do not miss my scheduled appointment.
Acceptance Criteria:
Use the Given-When-Then format.
* Given: The initial condition.
* When: The user performs an action.
* Then: The expected system outcome.
Each user story must have clearly defined acceptance criteria.
Tab 4: Conflicts, Duplicates & Missing Information
This is the application's most important differentiating feature.
The application must identify three categories:
A. Conflicts Found
Identify contradictory requirements or business expectations.
Example:
* Requirement 1: Project must launch within two months.
* Requirement 2: AI chatbot must be included in the initial release.
* Finding: Potential timeline and scope conflict.
B. Duplicate Requirements
Identify requirements repeated across multiple documents or conversations.
Example:
* Appointment reminder mentioned in both the meeting transcript and email.
C. Missing Information / Needs Clarification
Identify incomplete, ambiguous, or unconfirmed business requirements.
Examples:
* Cancellation refund policy: 50% refund or no refund after two hours?
* Report upload functionality: Confirmed or not?
* Language support: Is Hindi officially required?
Source Tracking:
Every identified conflict, duplicate, and missing requirement must display its source:
* Meeting
* Email
* WhatsApp
* Call Transcript
The application should also provide the original statement wherever possible for verification.
Tab 5: Traceability Matrix
Generate a structured Requirement Traceability Matrix (RTM).
Columns:
* Requirement ID
* Requirement Description
* Source Document
* Requested By
* Validation Status
Example:
FR-03 | Payment Failure Handling | WhatsApp Chat | Ramesh | Needs Clarification
Every requirement should be traceable to its original business source.
5. Human Validation & BA Review Panel
AI-generated requirements must not automatically be treated as approved business requirements.
The application must provide a human validation interface.
5.1 Requirement Validation
For every requirement, provide:
* Approve
* Needs Change
* Edit Requirement
* Add Comment
5.2 Editing & Comments
Users must be able to:
* Edit AI-generated requirement descriptions.
* Correct inaccurate information.
* Add comments explaining their decisions.
Example:
"AI hallucinated this requirement. The actual refund policy is still unclear."
5.3 Validation Dashboard
Display a live validation summary.
Example:
* Total Requirements Found: 12
* Approved: 9
* Needs Clarification: 3
The validation score must update automatically whenever a requirement's status changes.
6. Export & Documentation
The application must generate downloadable business analysis documents.
6.1 Export Formats
1. BRD:
   * Download as PDF.
   * Download as Word (.docx).
   * Include problem statement, scope, stakeholders, requirements, user stories, acceptance criteria, conflicts, and other relevant analysis.
2. User Stories:
   * Download as Excel (.xlsx).
   * Include user stories and acceptance criteria.
3. Traceability Matrix:
   * Download as Excel (.xlsx).
   * Include requirement IDs, descriptions, sources, requested stakeholders, and validation status.
4. Validation Report:
   * Download a report showing AI-generated requirements versus human-edited or corrected requirements.
   * Include approval status and reviewer comments.
All exports must reflect the latest human-validated information.
7. Sidebar: API Settings & Application Configuration
The sidebar must contain application settings and API configuration.
7.1 API Configuration
* Gemini API Key: Password-type input field.
* Test Connection: Button to verify API connectivity and key validity.
* Model Selection:
   * Gemini 1.5 Flash
   * Gemini 1.5 Pro
* Temperature Slider:
   * Low temperature for more consistent and accurate BA outputs.
   * Higher temperature for more creative analysis.
   * Default temperature should be kept low.
7.2 About Section
Display a short three-line application description:
"An AI-powered Business Analyst tool that transforms messy business information into structured requirements. It identifies conflicts, missing information, and duplicate requirements. It helps Business Analysts create BRDs, user stories, and traceability matrices faster."
8. Analysis History & Version Management
The application must support session-based analysis history.
8.1 Save Analysis
* Allow users to save the current analysis within the session.
* Maintain previously generated analysis versions.
8.2 Compare Versions
Provide a comparison between Version 1 and Version 2.
Highlight:
* Newly added requirements.
* Modified requirements.
* Deleted requirements.
* Changes in validation status.
* Changes made after human review.
8.3 Clear History
Provide a button to clear saved analysis history.

Overall MVP Acceptance Criteria
The MVP will be considered functional when:
1. Users can paste messy business information or upload supported files.
2. Users can load the City Care Hospital sample data without manually entering information.
3. Users can view and edit the Master Prompt.
4. Gemini API successfully processes the input and generates structured BA outputs.
5. All five output tabs display the correct categories of information.
6. Users can identify conflicts, duplicates, and missing information with source references.
7. Users can review, edit, approve, and reject AI-generated requirements.
8. Users can download BRDs, user stories, traceability matrices, and validation reports.
9. Users can configure API settings and model preferences.
10. Users can save analysis versions and compare changes.
Important: These are the eight functional modules currently defined in the scope. The original brief mentions ten mandatory features, but lists eight numbered modules. The ten acceptance criteria above consolidate the expected functionality without inventing two additional modules.
Final Product Goal: Build a practical AI-powered Business Analyst assistant that demonstrates the complete workflow from messy stakeholder communication to structured, validated, and exportable business documentation.
